## Scope and independence boundary

This is a read-only-plus-remediation review performed by the implementation
author at the user's request. It is useful as a defect audit, but it is not the
independent review required by the experiment gate.

## Initial verdict on commit 96f2ccb

`FAIL`

### Blocking findings

1. The E002 data-lock partitions were frozen in JSON but were not revalidated
   as pairwise disjoint by every execution entry point.
2. The tiled-proposer receipt was checked for checkpoint identity but not for
   the complete development-manifest, tile-manifest, data-lock, workbook and
   run-config lineage.
3. `freeze_for_test.py` trusted stored validation metrics and score selection;
   it did not recompute them from the frozen targets and proposal rows.
4. The test evaluator incorrectly required the development tile manifest to be
   sourced from the confirmatory manifest. A valid confirmatory run would
   therefore have failed before inference.

## Remediation

- Added `contracts.py` with pairwise partition and no-pixel-selection checks,
  and called it from preparation, training, evaluation and freezing paths.
- Bound training and evaluation to the exact development manifest, tile
  manifest, data lock, config and workbook hashes.
- Added validation targets and image-location identity to the evaluation
  artifact. The freeze step now re-reads the exact development manifest and
  recomputes baseline metrics, all repaired scoring arms, deterministic score
  selection, both oracle coverages and both deltas before issuing test
  authorization.
- Split tile-manifest validation correctly: validation requires its source to
  be the development manifest; test requires the exact development tile hash
  frozen in the authorization.
- Added tests for partition overlap, pixel-selected holdouts and the distinct
  validation/test tile-manifest contracts.
