## Minimal change

`research-decision-core` now keeps one short anchor inside the existing owner
note: original -> current question, relation/reason, scope authority and old-route
status. An existing scope-decision link suffices. Scope changes propagate to
owner/index and a corrected title or prominent scope label. A handoff carries
the anchor, active D step and advance/return/redirect condition.

Easier data do not replace the goal. Waiting/acquisition and scientific progress
remain separate. In-scope repairs do not gain a new approval stage. No per-turn
rewrite, new ledger, added review gate or bulk historical retrofit was introduced.

The local bootstrap points to this single maintained rule rather than copying it.
The installed core remains a symlink to this worktree's tracked source; existing
local overlays resolve to the updated bootstrap. This is not a claim that all
already-running HQs have re-read this new revision.

## Short HQ rule

Carry `original -> current goal + relation/authority + old-route status` together
with `active D + next scientific decision + return/redirect condition`. On a scope
change, update the owner and portfolio/index; distinguish access progress from
an answered question. Continue authorised repairs without another generic gate.
