## 二、`frexp` 派发边界和整数舍入正确

### 1. 普通分支确实排除了 tiny 结果

对非零有限输入，按你声明的 `frexp` 定义写成

\[
|x|=m_x2^{k_x},\qquad |t|=m_t2^{k_t},
\qquad \tfrac12\le m_x,m_t<1.
\]

令 \(k=k_x+k_t\)，则

\[
\tfrac14\,2^k\le |xt|<2^k.
\]

因此：

\[
k\ge-1020
\quad\Longrightarrow\quad
|xt|\ge2^{-1022}.
\]

这一分支的精确乘积不小于最小正规数，走原乘法在声明模型下不会因结果过小而需要 tiny 处理。大数乘积的 overflow 等异常仍应原样停止。

另一分支满足

\[
k\le-1021
\quad\Longrightarrow\quad
|xt|<2^{-1021}.
\]

这不仅包含次正规结果，也包含**第一个正规 binade 内的部分结果**。称其为“保守整数分支”比把其中每一项都称为“实际发生了下溢”更准确。

### 2. 以 \(2^{-1074}\) 为格距舍入，在该范围内是充分的

你给出的位型解码成立：

\[
x=(-1)^{s_x}M_x2^{e_x},\qquad
t=(-1)^{s_t}M_t2^{e_t}.
\]

非零正规数使用

\[
M=2^{52}+\mathrm{fraction},\qquad e=E-1075;
\]

非零次正规数使用

\[
M=\mathrm{fraction},\qquad e=-1074.
\]

令

\[
P=M_xM_t,\qquad e=e_x+e_t,\qquad h=e+1074.
\]

若 \(h\ge0\)，格点系数 \(P2^h\) 已经是整数，不需要舍入。若 \(h<0\)，令

\[
D_{\rm int}=2^{-h},\qquad
P=J D_{\rm int}+R,\qquad 0\le R<D_{\rm int}.
\]

则最近偶整数应为

\[
N=
\begin{cases}
J,&2R<D_{\rm int},\\
J+1,&2R>D_{\rm int},\\
J,&2R=D_{\rm int}\ \text{且 }J\text{ 为偶数},\\
J+1,&2R=D_{\rm int}\ \text{且 }J\text{ 为奇数}.
\end{cases}
\]

在保守分支的范围内，这个格点舍入正是 binary64 所需的舍入：次正规区间和紧邻其上的第一个正规 binade，间距均为 \(2^{-1074}\)。

符号由 \(s_x\oplus s_t\) 决定。负数可以先对绝对值作同样舍入，再加符号；舍入到零时必须保留该符号。输入为零时也必须先通过非有限检查，不能让“零快捷分支”接纳 NaN 或 Inf。

### 3. 封装可以更简单，但不能经过浮点缩放

这一区间的封装关系为：

| N 范围 | 指数字段 | fraction |
|---|---:|---:|
| \(0\le N<2^{52}\) | 0 | \(N\) |
| \(2^{52}\le N<2^{53}\) | 1 | \(N-2^{52}\) |
| \(N=2^{53}\) | 2 | 0 |

因此，在这个有限范围内，**正数的无符号编码恰好就是整数 N 本身**；再合入符号位即可。代码可以采用这个事实简化正规/次正规分界封装，但仍须检查范围、位序和 dtype，不能把 N 当作数值转换成 float。

这条简化不涉及另一种数值算法，也不扩大白名单。

### 4. 上沿进位的可达性要单独说明

对实际 binary64 输入，非零 `frexp` 尾数的最大值是 \(1-2^{-53}\)。因此，在整数分支中，

\[
\frac{|xt|}{2^{-1074}}
\le
2^{53}(1-2^{-53})^2
=
2^{53}-2+2^{-53}.
\]

最近偶舍入因而满足

\[
N\le2^{53}-2.
\]

**所以，\(N=2^{53}\) 是你保守封装范围中的边界，但不是该派发分支可达的乘积结果。** 支持它没有错误；测试规格应区分：

- 对实际输入对的端到端乘法测试；
- 对整数封装函数的边界测试。

不能为了满足“上沿进位”覆盖而伪造一对不可达输入，也不需要改变派发界来制造该案例。最大次正规与最小正规之间的舍入进位仍是真正需要覆盖的乘法边界。

### 5. 半量子误差证书的处理合理

这个分支中的绝对舍入误差满足

\[
|\operatorname{RN64}(xt)-xt|\le2^{-1075}.
\]

以符号、整数和二次幂形式记录，而不把该界转成 float 零，是正确的。它是**求值误差界**，不能加入比较容差。

证书还应区分“精确结果”“向较小绝对值舍入”“向较大绝对值舍入”。若报告的是实数轴上的向上/向下，负数时方向需要相应反转。整数分支计数、次正规输出计数、非零乘积舍入成零计数，也不应混为同一个“下溢次数”。

## 三、\(2^{-900}\) 分支确实保持原 binary64 限值，不是经验忽略

\mathrm{atol}

**这里可以直接返回同一个 atol，是因为能证明最终阈值逐位不变，不是因为相对项“看起来很小”。**

\[

该乘积远在正规区间内，可以按原乘法和加法求值。边界本身没有需要另加的容差或特殊通过规则。

## 四、直接比较与舍入比值的通过状态等价，论证成立

对已舍入的有限非负 d、有限正 denom，在正确最近偶除法模型下，

\[
d\le\mathrm{denom}
\quad\Longleftrightarrow\quad
\operatorname{RN64}(d/\mathrm{denom})\le1.
\]

你的关键论证成立。

当 \(d\le\mathrm{denom}\) 时，精确商不超过 1，最近舍入不会得到大于 1 的结果。

当 \(d>\mathrm{denom}\)，且正规分母位于

\[
\mathrm{denom}\in[2^e,2^{e+1}),
\]

最小可达正间隔给出

\[
d-\mathrm{denom}\ge2^{e-52}.
\]

于是

\[
\frac{d-\mathrm{denom}}{\mathrm{denom}}>2^{-53}.
\]

这严格超过 1 向上舍入邻域的半 ULP，故商不可能舍入回 1。次正规分母的相对间隔更大；最大有限分母之后没有更大的有限 d，也不存在遗漏案例。

所以，**不需要增加“d 超过阈值但比值仍舍入为 1”的虚构例外。**

需要保持两个边界：

**其一，这是结果判据等价，不是运行异常轨迹等价。** 原本多做一次无必要除法可能触发 overflow/underflow；删除这次运算后不会再触发它。此变化没有放宽通过阈值，但不能说新旧程序执行了相同异常事件。

**其二，通过判定仍必须覆盖全部分量。** 最大绝对差所在分量，不一定是最接近失败或已经失败的分量。你可以不保存最大 ratio，但应另外保存首个失败索引及其 d、denom；不能仅检查最大绝对差与“该项阈值”。

`close` 返回值没有调用方依赖，是本次给定前提，尚待源码审查确认。新 schema 可以取消浮点 ratio，但不得悄悄让其他调用方失去必要的失败信息。

## 五、Fraction 可以构成独立参考，建议用“舍入区间证书”而非复制候选算法

你的参考选择适合这个问题。Fraction 从实际 float 精确导入，可以表示精确输入及其乘积；不需要猜测 Decimal80 对任意次正规边界是否足够。

为避免候选与参考复制同一个商余数错误，独立 oracle 可以采用另一种验证组织：

1. 从输入的实际 float 值独立取得精确有理乘积。
2. 独立解码候选输出及其相邻 binary64 格点。
3. 检查精确乘积是否位于该输出的最近舍入区间内。
4. 若恰在中点，按输出有效数最低位的奇偶性裁决。

这不需要调用候选的除法、舍入或封装函数，也无需以一次危险 NumPy 乘法作真值。对于整数证书，还可以独立检查

\[

需特别注意，**Fraction 不保留负零的符号**；你将符号零另核，是必要的，不是重复检查。

测试除法判据等价时，也可以核对精确有理商与舍入区间，不必为了测试这条定理又执行会触发异常的浮点除法。
