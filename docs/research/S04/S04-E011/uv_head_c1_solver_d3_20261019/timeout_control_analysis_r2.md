## r2控制修订与下游联锁

1. 控制端stdout/stderr在Popen启动时就直写文件；事件记录开始、子PID/argv、
   超时界限、结束、字节数/路径、异常缓冲存在性与自有本地子进程组清理。
2. 远端未来固定脚本逐阶段和逐子命令begin/end，记录退出码、stderr及超时
   部分缓冲；-v保存SSH协议阶段信息。它们只是未来日志，不是当前观测。
3. 有效审批绑定后、任何Popen前安装SIGTERM→异常路径，和SIGINT一样写
   清理/终态；SIGKILL、断电或不可写盘仍无法保证落盘，缺失必须记未知。
4. 每个一次性步骤先排他claim；阶段失败后terminal拒绝后续步骤。只有计划内
   成功monitor才允许下一次观测（最多16次，至少60秒），不自动重连失败连接。
5. 新guard与worker PID/start_ticks/启动请求保留；报告冻结要求自有guard和
   已知worker退出且已有终态记录。身份缺失/未知时不复制仍可能变化的集合。
6. r2全新Run/root/archive/卡/计划hash；完整包锁定不变worker/square_root；
   在原100MiB内给控制诊断1MiB，正常producer阈值收紧为98MiB，终止回执1MiB。

科学worker、平方根方向、五源身份、原z主判据、PBD独立见证、25424分账、900秒
guard、8GiB RSS/CUDA、4GiB余量及失败不重试均沿原审结论。新控制与物化检查
只产生代码准备证据，不认证SSH恢复、资源现况、收敛或科学成功。
