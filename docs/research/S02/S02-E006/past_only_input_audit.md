# 如何判断当前输入是否使用未来数据

判据不是CSV里标了哪个cycle，而是当前输入的整个生成过程能否在未来数据不可见时独立完成。设当前特征 z(N)=f(raw<=N; parameters available by N or fixed from training specimens)。需要同时审原始数据依赖和参数/人工操作的来源。

1. 对每个输入列追溯到原始帧/传感器记录，列出DIC参考图、配准控制点、裂纹路径、裂尖窗口/ROI、插值邻域、滤波、标准化及人工修订。初始未加载参考图可能合法；以末帧裂纹路径、全序列极值/尺度、双侧时间平滑生成当前值，可能构成未来依赖。当前疲劳cycle的min/max图像对若在声明的origin之前均已采完，可合法使用，不能把cycle内载荷相位与未来疲劳cycle混淆。
2. 在与原处理相同的配置下做前缀重处理：隔离目录只提供截至N的原始帧/记录；从原图到当前特征重新生成。路径、ROI、参考和数据驱动参数也须仅用该前缀重新决定，或证明早在预测前已固定。不能把全序列算出的裂纹路径带入“前缀试验”，那会隐藏泄漏。取预先指定的早/中/晚起点，另有风险窗口可单独标为定向核验。
3. 与全序列版本在相同N的x/y、位移、固定ROI特征和mask/有效域比较。先用重复运行测定数值求解抖动，再设合理的实现一致性容差；该容差不是物理测量误差。若移除未来数据改变当前值，来源有未来依赖或流水线不一致，需要定位。无变化只支持被测试起点/配置的前缀不变性，还须审人工路径和隐藏缓存。

如果只有发布CSV/PT而没有原图、处理代码或完整记录，不能靠曲线平滑、正相关、cycle公式或“没有显式未来列”证明不存在泄漏。可取得作者的逐阶段说明/已有脚本和版本记录；证据不足时标未知，不能写无泄漏。

对本轮候选的落实：
- Mendeley：README给30cycle索引，不能证明DIC参考、裂尖路径、节点/ROI及PT处理的因果性。每帧内部的空间Griddata插值本身不等于时间泄漏，关键是它是否只使用同帧/已知参考和过去可得参数。
- FATACRACK：待作者确认路径提取、后向处理和末帧是否影响当前坐标/边界特征；现有冻结结果不变。
- PHM：同cycle两次waveform重复不算两条时间轨迹；需确认所发布sensor pair的选择在origin已可确定，而不是事后选择最终开裂路径。波形内time是脉冲采样时间，不是疲劳cycle。
- MnROAD：调查DAY和2023以后DATE_UPDATED不能自动证明当年可实时获取。核对原始调查/版本与修订；否则只能做按调查日期划分的回顾性发布标签验证。不能把当前汇总表里后补的调查/未来修正当作历史现场可用信息。

未来标签本来就可用于评价；它不得反向参与当前特征生成。按后来的维护记录删失评估窗口，是回顾性条件cohort选择，须单独声明，不等于在预测时已知道未来不会维修。

本次仅给出核验流程及缺口，没有重跑DIC、拟合预处理或训练模型。
